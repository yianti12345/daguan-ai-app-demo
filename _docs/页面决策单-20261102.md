# 页面决策单 · 三页（2026-11-02）

> 用法：改任何一页之前先答完这三行——**谁 / 他要做的哪个判断 / 做这个判断必须看到什么**。
> 三行没答完，不许出现尺寸、布局、弹窗还是抽屉（product-analyst §2）。
> 判据：页面上的每个数字与动作，都必须能回指这里的一行；回指不了的就是装饰。

## 1 应用管理（apps.html）

- **谁**：应用运营（内部），管 10 个应用的上架状态与版本。
- **判断**：① 这个应用现在能不能给客户用；② 有没有客户在用旧版本、要不要提醒；③ 新建后下一步去哪。
- **必须看到**：状态（已上架/未发布/已下架）、当前版本号与时间、**待升级客户家数**、组件可升级数。
- **动作后果**：上架/下架＝影响所有已授权客户（不可逆到"客户当场不能用"）；新建＝无副作用；客户授权＝跳到该应用的二级页。
- **现状缺口**：卡面「3 家待升级」只给数不给名单（点进客户授权才看得到是哪三家）——属可接受，因为判断 ② 只需要"要不要提醒"。

## 2 客户授权（client-auth.html?id=应用）

- **谁**：客户运营（内部），负责"哪家客户能用这个应用的哪一版"。
- **判断**：① 这家客户现在拿的是哪一版、比最新差几版；② 要不要给新客户开；③ 要不要收回。
- **必须看到**：租户名/ID、授权版本 vs 最新版本、授权时间、有效期、状态（已授权/已取消）。
- **动作后果分级**（按后果排序，越往下越重）：
  | 动作 | 可逆 | 影响谁 | 前置 |
  |---|---|---|---|
  | 升级到 vN | 可（再改回需要后端支持版本回退） | 这一家客户，立刻生效 | 无 |
  | 取消授权 | 可（恢复授权） | 这一家客户，立刻打不开 | 无 |
  | 删除记录 | **不可逆** | 只影响这条记录 | **必须已取消** |
- **现状缺口**：有效期只显示结束日，不显示"还剩几天"；长期用 9999-12-31 表示，与真实系统一致。

## 3 版本（versions.html）

- **谁**：应用运营。
- **判断**：① 线上是哪一版；② 某一版当时改了什么；③ 要不要把画布换成某一版再存新版本。
- **必须看到**：版本号、时间、摘要（改了什么）、当前线上标记。
- **动作后果**：查看＝只读；**替换＝把画布换成那一版（不建版本、不影响客户）**；存成新版本＝产生新版并推进版本号。
- **易错点**（已修）：原名「回到这一版」暗示版本号会倒退，与"版本只往前走"的模型冲突；现叫「替换」，并在确认框写明"客户不受影响，授权版本仍是 vN"。
