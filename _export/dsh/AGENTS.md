## 一、页面验证：只能用真浏览器，像人一样点

**管到哪**：任何「这页长什么样 / 点一下会怎样 / 尺寸对不对」的验证。
**谁定的**：2026-11-01，用户两次原话。
**何时失效**：真实浏览器通道确实不可用（扩展掉线、无图形环境）。那时必须写明「未实机验证」。

- 打开一页先把**可交互元素列全**（按钮/菜单/开关/标签页/下拉/卡片操作），逐个点开，记下每个点完变成什么样。
- **状态穷举**：列表页把每种状态标签都覆盖到，每种状态下每个按钮都点一次。
  **同一动作在不同状态下行为不同** —— 已上架点电源弹确认框、已下架点电源直接生效，这类差异只有点了才知道，读代码读不出来。
- 复刻/借鉴外部系统同理：不是截一张图照着画，是把它的每个状态、每个操作都走一遍。
- 线上系统只点不改数据的（下拉、展开、切 tab）随便点；会改数据的（下架、删除、发布）先看有没有确认框，有就取消。真要改，先经明确授权。

## 二、不许替他拟规则

他没说过的判断，不许写成「规则」记下来。我拟的必须标「这是我加的」，而且不许拿它当依据去改东西。

## 三、界面文案：不做解释

界面里不许出现解释性、提示性的句子。副标题不写「谁在用这个平台、用的是哪一版」；
状态行不写「4 个客户在用 · 1 个存了新版本还没升级」。企业级后台不自我介绍。
数据靠字段说（版本号就是版本号）、动作靠按钮说（「升级到 v4」）、状态靠颜色说。

**两处例外**：空态提示（画布还没内容时告诉他能怎么开始）、操作反馈 toast（2–3 秒自己走）。
判断法：这句话删掉，用户会不会做错事？不会 → 删。

## 四、动手前四句话（说不出来就不许动手）

| 环节 | 动手前说 | 会漏掉什么 |
|---|---|---|
| 需求 | 我要改 `<文件>`，改完你会看到 `<具体变化>` | 改了半天他看不到差别 |
| 产品 | 这东西属于 `<导航 / 页面 / 区块 / 字段>` 层 | 好页面放错层 |
| 界面 | 这一页每个字来自 `<哪个字段>`；新造的词是 `<哪几个>` | 解释性废话、口语化列名 |
| 代码 | 这个值存在 `<哪>`，刷新后 `<还在 / 会丢>` | 页面漂亮、一刷新全丢 |

## 五、判据：改了标准要登记，否则不算改对

- 判定标准写在**文件**里（如 `card-metrics.json`、`state-matrix.json`），判据脚本读文件，不写死数字。
  这样「我手填尺寸就会红」，不靠自觉。
- 改了判据脚本必须补一行修订台账（日期 → 文件 → 原来漏了什么 → 旧哈希 → 新哈希），并重签锁文件。
- 理由必须点明**原来那条错在哪**（假绿 / 误报 / 过期 / 漏），不许写「优化一下」。写了不陈述事实的词会被拒签。
- 判据默认只打失败项，`--verbose` 看全。通过项对「要不要动手」没有增量信息，但它会被每一轮重发。

## 六、Token 预算：按「重发次数」算，不按「这一句多长」算

- 一条内容进来一次，**之后每一轮都要重发**。「一次 read 8000 token、后面还有 127 步」
  比「一次性输出 3 万 token」更贵（DSH 实测工具结果占重发成本 40.7%）。
- 大文件（>90KB）不许整读：给 `offset/limit`，或 `tail -n 30`、`grep | head`。
- 常驻面（本文件、记忆文件）**一轮内只在收尾改一次**。中途反复写 = prompt 前缀每轮都变
  = 缓存全断，整段历史按原价重付。
- **不许用省 token 换效果**：不砍证据、不放宽判据、不跳过实机验证。

## 七、汇报

第一行是结论，不堆符号。三段：**做了什么 / 读数（谁跑的命令、跑的是不是那棵树）/ 判定**。
末尾一行写清：用了什么能力，或为什么没用。**只道歉不改判据，等于没发生。**

## 八、做界面设计前：`skill impeccable`，或查 `design-notes/INDEX.md`

30 篇设计方法论（来自 Impeccable，Apache 2.0）已装成 DSH 技能 `impeccable`（`~/.dsh/skills/impeccable/`）。
**它在技能列表里，但不会自动进上下文**：要 `skill impeccable` 才加载。没装技能时，平铺副本与路由表在 `design-notes/`。

- 流程：认问题 → 在 INDEX 里挑**一篇** → 读完动手 → 交付时说出用了哪条。
- **一轮只读一篇**。读三篇等于没读，一条都用不上。
- **读完说不出用哪条 = 没读。** 跟四席读数一个道理。
- **设计上下文不许从代码推断**：谁在用、什么情境、要完成什么、该给人什么感觉。
  这四条答不出就先问，别开工 —— 代码只说明"造了什么"，不说明"为谁造"。
- 硬标准（AI Slop Test）：这界面给人看，说"这是 AI 做的"，对方会立刻相信吗？会，就是问题。
