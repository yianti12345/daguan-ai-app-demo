# 视觉与交互验收

用证据评审界面，按影响排序给出可以执行的修复，必要时直接修改并复验。

## 检查维度

| 维度 | 检查内容 |
|---|---|
| 任务路径 | 首屏是否说明下一步，核心操作是否可发现、可撤销、可恢复 |
| 信息层级 | 标题、正文、辅助信息、操作和反馈是否有清晰权重 |
| 一致性 | token、组件变体、间距、图标、文案和状态是否统一 |
| 响应式 | 320px 起的窄屏、平板、桌面、宽屏和文本放大是否保持核心任务 |
| 无障碍 | 语义 HTML、键盘路径、焦点、对比度、替代文本、表单错误和动效偏好 |
| 状态覆盖 | 空、载入、错误、成功、禁用、权限不足、网络失败和长文本 |
| 工程质量 | 资源加载、控制台错误、布局抖动、重复渲染和不必要的依赖 |

## 评审方法

1. 先记录环境、入口、视口和复现步骤。
2. 每个发现写清位置、证据、用户影响、优先级和修复建议。
3. 优先修复阻塞任务、数据丢失、严重无障碍和核心流程错误。
4. 修复后重新执行原步骤；没有证据就不要声称已解决。

## 输出

使用 P0–P3 分级的问题表；最后给出“已验证”“部分验证”“未验证”三类结论和下一步操作。
